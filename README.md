# akandejjohn

Portfolio website for **John Akande** (@akandejjohn), a figurative artist based in Lagos.

A static site: plain HTML, `styles.css`, `script.js` and `assets/`. Nothing needs building to deploy it.

## Pages

| Page | File |
| --- | --- |
| Home (ends with a short FAQ; edit the questions in `FAQS` in the script) | `index.html` |
| Works (the catalogue, with filters and a currency switch) | `works.html` |
| One page per painting | `works/<painting>.html` |
| About (biography, studio film, artist statement) | `about.html` |
| Commission | `commission.html` |
| Contact (enquiry form) | `contact.html` |
| Page not found | `404.html` |

Links and asset paths start with `/`, so preview the site through a local server (below), not by opening the files directly.

## Preview locally

```bash
python3 -m http.server 8000
```

Then open http://localhost:8000.

## Editing pages and adding paintings

The pages are generated by `tools/build_pages.py`, so the navigation, footer and painting details live in one place. After editing it, regenerate every page:

```bash
python3 tools/build_pages.py
```

- **Painting details** (title, size, price, sold) are in `tools/works.json`. Each entry is `[file name, title, size, price, sold, [image width, image height]]`.
- **Adding a painting:** put a JPEG (longest side about 1600 px) in `assets/img/works/`, add its entry to `tools/works.json`, run `python3 tools/make_images.py` to make its WebP sizes, then run `python3 tools/build_pages.py`.
- **Framing a painting:** photos without a frame can be put into the catalogue's gold gallery frame with `python3 tools/frame_artwork.py <photo> <width> <height> <out.jpg>`, using the painting's real size for its proportions (e.g. `36 48`). The unframed photos are kept in `assets/img/works/originals/`.
- **Images:** each painting has the original JPEG plus WebP copies at 480, 800 and 1200 px wide and at full width (for example `young-virtuoso-i-800.webp`). Pages let each device download the size it needs. `tools/imgs.json` lists the widths that exist for each image.

Pages edited by hand will be overwritten the next time the script runs, so make lasting changes in the script.

## Search, sharing and icons

- `sitemap.xml` and `robots.txt` help search engines find every page. Both are written by the script.
- Each page has its own share preview (`assets/og/`), and each painting's page uses the painting itself.
- Pages include structured data, a format search engines read: the artist on Home and About, and each painting with its size, price and availability.
- Icons: `favicon.ico`, `assets/icons/` and `site.webmanifest`.

## Visitor analytics

Pages load Vercel Web Analytics. To start collecting data, open the project on vercel.com, go to **Analytics** and click **Enable**. Until then the script does nothing.

## Enquiries, print requests and payment

- **Contact form** (`contact.html`): there's no server. Pressing "Send enquiry by email" opens the visitor's email app with the message addressed to John (johnakande23@gmail.com), the subject and their note already filled in.
- **Request a print** (each painting page): opens an email to John asking for a print of that painting.
- **Payment details**: John's bank accounts are on `contact.html#payment`, and each available painting's page links to them.

The email address and bank details are set at the top of `tools/build_pages.py` (`EMAIL`, `BANK_ACCOUNTS`); change them there and rebuild.

## Deploy

Any static host works (Vercel, Netlify, GitHub Pages, Cloudflare Pages). Point it at the repo root. `404.html` is used automatically for missing pages on Vercel and Netlify.
